§ 02 — System architecture

Three tiers, one process each

Browser-resident SPA talks to a stateless API over HTTP. The API loads JSON files into memory once at startup and filters in-process. Restart reloads the data.

§ 03 — Tech stack

Dependencies, by tier

Mainstream choices on both sides. Frontend leans on Vue's official ecosystem; backend stays close to FastAPI defaults.

Tier 1

Frontend

  • Vue^3.4.21
  • vue-router^4.3.0
  • axios^1.6.7
  • Vite^5.2.0
  • @vitejs/plugin-vue^5.0.4
Composition API throughout. No state library — composables hold singletons. Custom SVG charts, no Chart.js.

Tier 2

Backend

  • FastAPI≥0.110
  • Uvicorn≥0.24
  • Pydantic≥2.5
  • Python≥3.11
  • uv (package mgr)—
Single-file app. Pydantic validates both inbound query params and outbound response shapes via response_model.

Tier 3

Data & tests

  • JSON files7 files
  • pytest≥8.0
  • pytest-asyncio≥0.23
  • httpx≥0.27
  • pytest-cov≥4.1
No database, no ORM, no migrations. Mutations to data don't persist across restarts. Tests use FastAPI TestClient.
§ 04 — Data flow

One request, end to end

A user adjusting the warehouse filter triggers a re-fetch on the active view. The trip from click to repaint passes through six layers — each one narrow and replaceable.

§ 05 — API surface

Endpoints

All endpoints are GET. Filters are optional and shared by convention: warehouse, category, status, month (or quarter Q1-2025).

Method Path Filters Purpose
GET/—Health / version banner
GET/api/inventorywarehouse, categoryList inventory items
GET/api/inventory/{id}—Single item lookup
GET/api/orderswarehouse, category, status, monthList orders (the only endpoint exercising all four filters)
GET/api/orders/{id}—Single order
GET/api/demand—Demand forecasts (no filtering)
GET/api/backlog—Backlog items, joined with purchase-order existence flag
GET/api/dashboard/summarywarehouse, category, status, monthAggregates: inventory value, low-stock count, pending orders, backlog count
GET/api/spending/summary—Cost totals + period-over-period change
GET/api/spending/monthly—Monthly spending series
GET/api/spending/categories—Spending split by category
GET/api/spending/transactions—Recent transactions ledger
GET/api/reports/quarterly—Quarterly rollups (computed at request time from orders)
GET/api/reports/monthly-trends—Month-over-month order count + revenue
